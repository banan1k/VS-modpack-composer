# Vintage Story Modpack Builder

Локальный каталог модов Vintage Story с веб-интерфейсом и Discord-ботом. Каталог собирается из форумных каналов Discord и данных Vintage Story Mod DB; моды можно искать, фильтровать, выбирать и упаковывать в ZIP-сборки с проверкой зависимостей и совместимости.

## Установка

Нужен **Python 3.12 или новее**. Склонируй репозиторий и перейди в его папку:

```bash
git clone https://github.com/banan1k/VS-modpack-composer.git
cd VS-modpack-composer
```

Создай виртуальное окружение, установи проект и запусти веб-приложение.

**Windows PowerShell** (либо просто запусти `start.bat` после настройки `.env`):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**Linux / macOS:**

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открой `http://127.0.0.1:8000`. Для Windows в проекте также есть `start.bat`: он запускает сервер и сохраняет вывод консоли в `data/logs/server-console.log`.

## Настройка Discord

Создай приложение и бота в Discord Developer Portal, добавь бота на сервер и скопируй `.env.example` в `.env`. Укажи токен, ID сервера и все форумные каналы с модами:

```env
DISCORD_TOKEN=...
DISCORD_GUILD_ID=123456789012345678
DISCORD_FORUM_CHANNEL_IDS=111111111111111111,222222222222222222,333333333333333333
```

`DISCORD_FORUM_CHANNEL_IDS` — список **ID именно форумных каналов**, разделённых запятой или `;`. Для публикации сборок можно дополнительно задать `DISCORD_BUILDS_CHANNEL_ID`, а для запросов неизвестных зависимостей и машинного реестра — `DISCORD_REGISTRY_CHANNEL_ID`.

В Discord Developer Portal включи **Bot → Privileged Gateway Intents → Message Content Intent**. Боту нужны права на просмотр форумов, чтение истории сообщений и отправку сообщений в каналы сборок/реестра. Для команды синхронизации форумных тегов у бота должно быть право **Manage Channels** во всех перечисленных форумах. Пользователю, который запускает эту команду, также требуется Manage Channels.

### Теги форумов

Теги каталога берутся из тегов, назначенных темам в Discord Forum Channels. Создай нужные теги в одном форуме и назначай их соответствующим темам модов. После синхронизации каталога теги появятся на карточках и в фильтре сайта.

Чтобы перенести список **определений тегов** (названия, эмодзи и признак модерации) из одного форума во все остальные каналы из `DISCORD_FORUM_CHANNEL_IDS`, используй slash-команду:

`/sync-forum-tags source_channel: <исходный форум>`

Выбери форум, который будет источником истины. Команда предварительно проверяет каналы и права бота, затем заменяет список тегов в остальных настроенных форумах. Команда синхронизирует определения тегов и сохраняет локальные ID совпадающих тегов (а также тегов, переименованных на той же позиции). Она **не переносит назначения с тем исходного форума в другие темы**; уже назначенные теги целевых тем остаются привязанными к сопоставленным определениям. После изменения тегов выполни обновление каталога кнопкой «Обновить», чтобы изменения попали в локальную базу.

## Использование каталога

- Ищи по названию, `modid`, описанию и тегам.
- Выбирай один или несколько тегов в фильтре справа от строки поиска. Если выбрано несколько тегов, отображаются моды, у которых присутствуют **все** выбранные теги.
- Меняй сортировку на «Название», «Теги» или «Версия мода». Первое нажатие выбирает сортировку, повторное нажатие на активный вариант меняет направление. По умолчанию используется алфавитный порядок; версии сортируются от новых к старым.
- Выбирай карточки и создавай сборку. До создания приложение проверяет обязательные зависимости, конфликты и наличие релизов для целевой версии Vintage Story.
- После создания сборку можно опубликовать в Discord и скачать ZIP. Ссылка `/build/{share_id}` позволяет открыть состав сборки на другой машине.

На сайте используются фиксированные цвета для стандартных тегов: Survival — красный, Crafting — оранжевый, Building — коричневый, Exploration — голубой, Nature — зелёный, Combat — графитовый, Cosmetic — жёлтый, Visual — розовый, QoL — серый и Lib — фиолетовый. Любые дополнительные теги тоже отображаются: им автоматически назначается устойчивый дополнительный цвет.

## Данные и обслуживание

- Настройки хранятся в `.env`; локальная база — `data/app.db`; кеш архивов и изображений — в `data/cache/`.
- При обновлении проекта сохраняй `.env` и папку `data`. Схема SQLite мигрируется при запуске; удалять базу для установки новой версии не нужно.
- `MAX_VINTAGE_STORY_VERSION` задаёт целевую версию Vintage Story для каталога и фоновой предзагрузки. Одновременно запускается ограниченное число загрузок, а пользовательские операции получают более высокий приоритет.
- Веб-приложение пишет логи в `data/logs/app.log`; Windows launcher дополнительно пишет `data/logs/server-console.log`.
- Если пользователи Discord должны открывать опубликованные сборки, задай `PUBLIC_BASE_URL` как доступный им адрес. `http://localhost:8000` работает только на той же машине.

## Разработка и тесты

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
```

Проект использует FastAPI, discord.py, SQLAlchemy asyncio и SQLite. Mod DB API используется для метаданных модов и релизов; URL архивов берутся из ответов API или восстановленных данных кеша, а не конструируются из ID вручную.

## Changelog

### Формат версий

Начиная с версии **0.4.5**, проект использует публичную схему `MAJOR.MINOR.PATCH` (SemVer): `PATCH` — исправления без изменения пользовательского функционала, `MINOR` — новые обратно совместимые возможности, `MAJOR` — значительные несовместимые изменения после выхода на стабильную ветку. Пока проект находится в линейке `0.x`, новые функциональные этапы повышают номер `MINOR`. Предыдущие внутренние сборки с номерами `0.8.x–0.10.x` отражали промежуточные итерации разработки; их изменения сохранены в истории ниже, а публичная линейка продолжается от `0.4.5`.

### 0.5.1 — исправления каталога и синхронизации тегов

- Исправлена компоновка панели каталога: строка статуса теперь находится над поиском, а фильтр тегов и сортировка выровнены в одной строке с поиском на широких экранах.
- Переработано оформление выпадающего списка тегов в стиле сайта; для CSS и JavaScript добавлены версии в URL, а HTML-страницы требуют перепроверки кеша, чтобы браузер не продолжал использовать старые файлы интерфейса.
- Исправлено адаптивное размещение элементов управления на небольших экранах.
- Синхронизация повторно сверяет сохранённые теги мода с текущими назначениями Discord даже при совпадающем fingerprint, восстанавливая пропущенные ранее данные.
- Добавлен fallback извлечения названий назначенных тегов по ID родительского форума и диагностический итог сканирования с количеством размеченных тем и перечнем тегов.

### 0.5.0 — теги, фильтры, сортировка и управление тегами Discord

- Теги тем Discord теперь сохраняются в локальном каталоге и включаются в fingerprint источника, поэтому изменение тегов приводит к обновлению записи при следующей синхронизации.
- Добавлено отображение тегов под названием мода. Для десяти стандартных тегов задана согласованная цветовая палитра: Survival, Crafting, Building, Exploration, Nature, Combat, Cosmetic, Visual, QoL и Lib. Дополнительные теги тоже поддерживаются и получают устойчивый цвет.
- Добавлен выпадающий фильтр тегов рядом с поиском. Можно выбрать несколько тегов; при множественном выборе мод должен содержать каждый из выбранных тегов. Поиск также учитывает названия тегов.
- Добавлено меню сортировки по названию, тегам и версии мода. Начальный порядок — алфавитный; версия сортируется от более новой к более старой. Повторный выбор активного пункта переключает направление.
- Добавлена slash-команда Discord `/sync-forum-tags`: копирует определения тегов, эмодзи и признаки модерации из выбранного исходного форума во все остальные форумы в `DISCORD_FORUM_CHANNEL_IDS`. Предварительно проверяются типы каналов и права бота; ответы команды скрыты от остальных участников.
- Добавлена миграция поля `tags_json` для существующей SQLite-базы. Существующая база и кеш остаются на месте. После обновления версия fingerprint источника повышается, поэтому при первой синхронизации старые записи форумных модов могут быть обновлены повторно.
- README переписан для GitHub: краткое описание, установка, настройка Discord и тегов, описание использования, обслуживание и единый changelog.

### 0.4.5 — последняя версия предыдущего этапа

- Исправлена обработка метаданных при фоновой предзагрузке: функция проверки совместимости `is_version_compatible` импортируется корректно. Ранее из-за `NameError` обработка множества архивов завершалась одной и той же ошибкой.
- Добавлен fallback на V2 endpoint последнего релиза Mod DB, если `install-information` не возвращает файл для целевой версии игры. Ссылки, имя файла и версия сохраняются в сборке и могут использоваться для восстановления старых сборок.
- Усилено восстановление загрузок по кешу и данным старых релизов; добавлена диагностика для модов, у которых не удалось найти скачиваемый файл.
- Добавлено версионное сопоставление одинаковых имён архивов между разными релизами и устранена дублирующая запись `modpack.json` при сборке ZIP.
- Сохранены тесты разрешения релизов и prefetch, проверка компиляции и целостности сборки.

### Предыдущая история до 0.4.5

- **Основа каталога:** локальное FastAPI-приложение, карточки модов, поиск, выбор состава сборки, создание ZIP и кеширование файлов.
- **Discord ingestion:** явный список Forum Channel ID, сбор стартовых сообщений тем и сообщений дополнений, инкрементальная синхронизация по fingerprint источника и запись локального registry как `mod-registry.txt`.
- **Метаданные Mod DB:** раздельное хранение внутреннего API ID, публичного asset ID и игрового `modid`; получение названия, описания, обложки, поддерживаемых версий и релизов с резервным разбором HTML-страницы.
- **Зависимости и связи:** анализ API и описания Mod DB, типы отношений (зависимость, совместимость, конфликт, дополнение), confidence и проверка недостающих обязательных зависимостей до создания сборки. Низкоуверенные связи сохраняются для просмотра, но не блокируют сборку.
- **Сборки и Discord:** share ID для открытия сборки на другой машине, публикация Embed и `modpack.json`, восстановление сборок из новых и исторических Discord-сообщений.
- **Фоновая предзагрузка:** ограничение конкурентных загрузок, приоритет пользовательских запросов, чтение `modinfo.json` из ZIP, извлечение точных зависимостей и обновление каталога без повторного сканирования Discord после завершения фоновой задачи.
- **Библиотеки и зависимости:** встроенные компоненты `game`, `survival` и `creative` исключены из стороннего каталога; известные библиотечные зависимости могут импортироваться автоматически, остальные формируют устойчивые запросы для добавления в Discord.
- **Кеш и база:** читаемые каталоги файлов по имени мода, миграция старых путей кеша, SQLite WAL и `busy_timeout`, миграции схемы, удаление дублирующихся связей без нарушения уникальных ограничений и хранение логов с ротацией.
- **Внутренние итерации 0.8.0–0.10.3:** восстановление старых каталогов при смене алгоритмов; извлечение точных зависимостей; очистка и миграция кеша; разбор Mod DB идентификаторов; разрешение конфликтующих отношений; восстановление URL релиза через V2 API; исправления проверки совместимости в prefetch.
